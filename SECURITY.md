# Security Policy

## Supported Versions

Security fixes are provided for the latest published release of Elasticsearch Monitoring. Please upgrade to the latest compatible version before reporting an issue. Older releases may not receive security patches.

## Reporting a Vulnerability

Please do **not** report suspected vulnerabilities in public GitHub issues, discussions, pull requests, or social media.

Use GitHub's private vulnerability reporting feature for this repository ("Report a vulnerability" under the Security tab). If private reporting is unavailable, contact the repository owner privately through GitHub.

Include, where possible:

- The affected package version and the Laravel, PHP, and Elasticsearch versions.
- A clear description of the potential security impact.
- Reproduction steps or a minimal proof of concept.
- Relevant configuration details, with secrets and personal data removed.

Do not include Elasticsearch credentials, API keys, private endpoints, production data, or customer records in a report. Use placeholders for sensitive values.

## Disclosure

Please allow reasonable time for investigation and a fix before publicly disclosing a vulnerability. We will coordinate a disclosure timeline with the reporter where possible.

We cannot guarantee a response or remediation deadline, but reports will be reviewed as soon as reasonably possible.
